# REMANSO — Addendum B (supersedes any earlier co-op addendum): ONLINE two-player, each on their own computer

## Client decision (final, reaffirmed)
Two players, two computers, each with mouse and keyboard, over the internet. Still ONE self-contained .html with no assets from the network. The network is used ONLY for multiplayer: a public signaling relay to exchange the WebRTC handshake, public STUN/TURN for NAT traversal, then a direct peer-to-peer DataChannel. Solo play must never touch the network.

## Player experience
- Solo is the default and unchanged. In the sky band, top-right, a faint serif word **"a dois"** (alpha 0.35, hover/touch 0.8) with two tiny dots (teal, rose) joined by a hairline. Clicking it opens the **lobby**: a small DOM overlay (not canvas) centred in the sky band, same palette and serif stack as the game (background rgba(5,8,20,0.78), 1 px border rgba(242,232,213,0.18), radius 14 px, text #f2e8d5, no backdrop-filter). Escape or clicking outside closes it and cancels any pending room.
- Lobby has two verbs: **"Criar um mar"** and **"Entrar num mar"**.
  - Create → shows a 6-letter code in large letter-spaced serif (e.g. `TOVANE`), a "copiar" link, and a status line with a breathing dot: "esperando a outra mão…". When the friend connects: "conectado", the panel fades (0.6 s), the diegetic line *"Duas mãos lembram mais."* / *"Two hands remember more."* plays once, and BOTH games restart the arc together from Act 0 (see Netcode).
  - Join → one input (auto-uppercase, letters only, 6 chars) + "entrar". Status: "procurando…" → "conectando…" → "conectado". Unknown code after 10 s: "ninguém nesse mar" and the input stays.
  - If the signaling relay cannot be reached (all brokers fail) or the peer connection fails: status "o mar não respondeu" + link **"trocar código à mão"** → Manual mode.
  - **Manual mode** (always works if the two can exchange text on WhatsApp/Discord): Host: a textarea "convite" (read-only, the compressed offer) with "copiar", then a textarea "cole a resposta aqui" + "conectar". Guest: textarea "cole o convite aqui" + "responder" → shows "resposta" textarea with "copiar". Both sides then connect. Codes are prefixed `RM1.` and are base64url of deflate-raw (via CompressionStream; fall back to plain base64url when CompressionStream is unavailable; the decoder accepts both).
- During online play: a tiny indicator top-right of the sky, two dots joined by a hairline (teal = host, rose = guest, local player's dot brighter). If the peer's inputs stall > 400 ms the remote dot pulses; after a disconnect (DataChannel closed, or stall > 10 s) the line *"A outra mão se foi."* / *"The other hand is gone."* plays once, the remote pointer is released, and the game continues SOLO from the current state without waiting. "a dois" returns 3 s later.
- Both players see the same sea, the same glyphs, the same sky. Host's pointer = P1 (teal ring/rim/beads), guest's = P2 (rose ring, rim ramp rose→amber→white, pad starts a fifth above). Both hands have both verbs. Co-op synergy: while a remanso is open and the OTHER hand stirs within 2R of its centre, that remanso's recall weight w ×1.25 and rim strain uses |v|×0.7; the rim shows a thinner second counter-rotating dash in the partner's tint. Overlapping remansos: max w per cell; beads light in sync. Idle demo and stuck-nudge are disabled online (they would be nondeterministic and patronizing with a friend).
- Local two-finger touch on one device stays as in the GDD (P2 = second finger). The keyboard-driven second cursor from the earlier addendum is CUT (not needed: each player has a mouse).

## Signaling (relay) — MQTT 3.1.1 over WebSocket, hand-written client (~120 lines), no libraries
- Brokers tried in order, 4 s connect timeout each, first CONNACK wins: `wss://broker.emqx.io:8084/mqtt`, `wss://broker.hivemq.com:8884/mqtt`, `wss://test.mosquitto.org:8081`. `location.hash` may contain `broker=ws://127.0.0.1:PORT` (accepted ONLY for localhost/127.0.0.1) — the test harness uses this with a mock broker.
- Packets: CONNECT (protocol name "MQTT", level 4, clean session, keepalive 30, clientId `rm` + 10 random base32 chars from crypto.getRandomValues), SUBSCRIBE (QoS 0) to topic `remanso/1/<CODE>`, PUBLISH QoS 0 retain=false, PINGREQ every 20 s, DISCONNECT on success/close. WebSocket subprotocol `mqtt`, binaryType arraybuffer. Parse remaining-length varint; ignore unknown packet types.
- JSON messages on the topic: `{t:'join', id}` (guest, repeated every 2 s until an offer arrives, max 10 s), `{t:'offer', id, to, sdp}` (host → first guest; other joins get `{t:'busy', to}`), `{t:'answer', id, to, sdp}` (guest). Own messages are ignored by `id`. Both sides unsubscribe + DISCONNECT once the DataChannel opens.
- Room code: 6 letters CVCVCV, consonants `BDFGJKLMNPRSTVZ`, vowels `AEIOU` (421,875 combos), from crypto.getRandomValues. Host waits up to 10 minutes; then the room closes ("o mar adormeceu").
- ICE: `stun:stun.l.google.com:19302`, `stun:stun1.l.google.com:19302`, `stun:stun.cloudflare.com:3478`, and TURN `turn:openrelay.metered.ca:80`, `turn:openrelay.metered.ca:443`, `turns:openrelay.metered.ca:443?transport=tcp` (username/credential `openrelayproject`, a public free relay; if it is down ICE simply ignores it — say so in a code comment, never in the UI). Non-trickle: wait for `iceGatheringState === 'complete'` or 2.5 s, then send `localDescription.sdp`. DataChannel `game`, ordered, reliable. Connection timeout 15 s → failure path.
- Absolutely no other network use. `fetch`, XHR, `<script src>`, `<link href>`, `import()` remain forbidden.

## Netcode — deterministic lockstep (the only scheme that fits a 20k-cell fluid on a single file)
- Both peers run the identical simulation; only INPUTS cross the wire. Determinism is therefore a hard requirement of the sim (rules below apply in SOLO too, so there is one code path).
- Handshake on DataChannel open: guest → `{t:'hi', v:1, rung}`; host → `{t:'hello', v:1, seed, rung: max(hostRung, guestRung) /*coarser wins*/, delay}`; then 8 ping/pong messages over 1 s to measure RTT; `delay = clamp(ceil((RTT/2)/16.7) + 2, 3, 10)` ticks (host decides, included in `{t:'start', delay, at: 0}`). Both call `restartOnline(seed, rung, delay)`: fields cleared, history count = 0, director → Act 0 at tick 0, calibration skipped, GS sweeps fixed at 10, quality ladder restricted to render-only steps (grain, bloomA, motes, main scale), time scale locked at 1.
- Tick = one fixed 60 Hz sim step, numbered from 0. At each local tick T: sample the local pointer(s) → input for tick T+delay, store locally, send `{ordered, binary}` packet: `u32 tick, u8 n, n × (u16 x, u16 y, u8 flags)` where x,y are water-normalized in 1/65535 units (0xFFFF = no pointer), flags bit0 = pressed. Tick T executes ONLY when the remote input for T is known; otherwise the loop stalls (renders the last state, counts a stall, shows the pulsing dot after 400 ms). Ticks are capped at 6 per frame when catching up. The local cursor RING follows the raw pointer immediately; its EFFECT on the water lands `delay` ticks later (67–170 ms) — the design tolerates this; the sea is slow.
- ALL game-logic time derives from the tick count (`t = tick·DT`): act timers, stamping, coherence cadence (tick % 6), snapshot cadence (tick % 3), weather phase, glyph timers, tells. Real time is allowed only for cosmetics (text fades, audio envelopes, cursor breathing, star twinkle, grain offset, lobby UI).
- Pointer processing order: by player index (host P1 first, guest P2 second), never by arrival.
- Determinism rules for every sim path (FLUID, HISTORY, REMANSO, GLYPHS, WEATHER, director): no `Math.random`; no `Math.sin/cos/tan/exp/log/pow/atan2/hypot` — use `dsin/dcos` (range reduction to [-π, π] then an odd polynomial with only +,−,×; ≤ 1e-6 error is fine) and replace Gaussian kernels with the compact polynomial `g(r) = (1 − (r/Rk)²)²` for r < Rk (Rk = 3σ), or precompute kernels with a hand-written `dexp` (range reduction + Taylor 10 terms). `Math.sqrt/floor/ceil/round/abs/min/max/sign/trunc` are IEEE-exact and allowed. Typed-array stores are allowed. Iteration order is fixed. No dependence on frame rate, screen size, DPR, quality step, or wall-clock inside the sim.
- Screen independence: the sim works in CELLS. The pointer is converted CSS px → water-normalized → cells at sampling time; stillness uses cell-space speed (`STILL_CELLS = 6 cells/s`, the mean over the 150 ms ring — 40 px/s at 1280x720, rung 0), remanso radius in cells (`R = (60 + 140·ease)·kScale px` becomes `R_cells = (7.5 + 17.5·ease)` at rung 0; floor 5.5 cells); both scaled by `gridK = sqrt(N / MAX_CELLS)` (1 at rung 0 whatever the aspect, 160/192 and 128/192 at the coarser rungs). Rendering converts cells → px per screen. Two different monitors must produce bit-identical sims.
- Motes, sparks, star flights, fossil, text and audio are render-only and may stay nondeterministic; they never feed the sim.
- **Desync detection**: every 60 ticks both peers compute `stateHash()` = FNV-1a 32-bit over: `round(Σdye0·1000)`, `round(Σdye1·1000)`, `round(ΣdyeW·1000)`, `round(Σ(|u|+|v|)·100)`, each glyph's state id and coherence bucket `round(coh·100)`, director act index, history head/count, weather tick. Exchange `{t:'h', tick, hash}`; keep the last 8 local hashes; compare by tick. On mismatch → **resync**: host serializes at the next multiple-of-60 tick S: dye0/1/W quantized u8 (3·N), u/v i8 (2·N, ×3 clamp ±127), glyph states + timers, director state, remanso depth reset → chunked ≤ 15 KB messages `{t:'sync', at: S, i, n}` + binary. Guest stops ticking at S until all chunks are applied; both set history count = 0 at S and every remanso's depth d = 0; a soft recall-coloured flash (0.12 → 0 over 0.6 s) makes the correction read as a wave passing. Count resyncs in stats(). Log a `console.warn` once per resync (this is the ONLY allowed console output).
- Disconnect: `close`/`error` on the DataChannel or `connectionState` failed/disconnected > 10 s, or input stall > 10 s → solo continuation as described above.
- Visibility: a hidden tab stops rAF; the peer stalls and shows the pulsing dot; on return the accumulator resumes and ticks catch up (≤ 6 per frame). No special casing beyond the existing visibilitychange handling; do NOT disconnect on hide.

## Debug API additions (harness depends on them exactly)
```js
window.__game.net = { mode: 'solo'|'host'|'guest', state: 'idle'|'signaling'|'connecting'|'connected'|'lost', code: 'TOVANE'|null, tick, delay, stalls, resyncs, rtt, lastHash };
window.__game.netCreate()                  // → Promise<string code> (opens the room via the relay; uses #broker override if present)
window.__game.netJoin(code)                // → Promise<void> resolves when the DataChannel is open
window.__game.netManualOffer()             // → Promise<string> the RM1. invite
window.__game.netManualAnswer(offerStr)    // → Promise<string> the RM1. response (guest side)
window.__game.netManualAccept(answerStr)   // → Promise<void> (host side) resolves when open
window.__game.netLeave()                   // closes everything, returns to solo
window.__game.stateHash()                  // → { tick, hash }   computed NOW (same function the netcode uses)
window.__game.hashLog()                    // → [{ tick, hash }] the last 16 hashes taken at ticks that are multiples of 60 (kept in solo too)
window.__game.debugPerturb()               // adds 0.02 to one dye cell (harness-only nondeterminism injection; harmless)
window.__game.scriptInput(events)          // queue [{ tick, x, y, down }] (x,y water-normalized 0..1, or null for no pointer) consumed at EXACT ticks
                                           //   through the same per-tick input path the netcode uses for the local player; used by the determinism test
snapshot().pointers                        // → [{ player: 1|2, local: bool, kind, x, y, down, still, s, d }]
snapshot().net                             // → same object as __game.net
```

## Acceptance additions
1. `harness/net.js` (two pages in one Chromium, no network): connects via the mock MQTT broker path AND via the manual path; both must reach `connected` within 10 s.
2. Lockstep integrity: with both bots playing (host P1, guest P2), `stateHash()` compared by tick between the two pages is EQUAL for every sampled tick over a 4-minute run at `--viewport 1280x720` on the host and `--viewport 1600x900 --dpr 2` on the guest (different screens, identical sim). Zero mismatches without perturbation.
3. Resync: after `debugPerturb()` on the guest, hashes diverge and re-converge within 3 s; `resyncs === 1`; no errors; the game continues and the arc still reaches Dawn.
4. Disconnect: closing the guest page makes the host show the "outra mão" line within 11 s and continue ticking solo; no errors.
5. Solo mode makes NO network connection (Playwright `page.on('request')` sees zero requests, `page.on('websocket')` sees none). Online mode makes WebSocket connections only to the broker list (or the #broker override) and no HTTP requests.
6. Determinism regression: two SOLO pages with the same seed and the same scripted input log (fed through `pointer` events at identical ticks via the harness) produce identical `stateHash()` at tick 3600 on 1280x720 and 1920x1080.
